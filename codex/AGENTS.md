# ルール
- 文章を書くとき、ユーザーのタイポミスは直して書く。
- ユーザーの利益を追求すること。
- 先に決めておいた方が今後のためになる事があれば指示よりも先にユーザーに質問すること。
- ユーザーが指示していない場合先にこれから行う変更を言うこと。
- コマンドや運用で詰まった場合は、今後の改善のためユーザーに報告する。
- 必要であればweb検索を使ってよい。
- 検索時は必要なら英語検索もすること。
- ユーザーの利益を優先すること。
- 大きな変更の前にはコミットを促すこと。
- サイトを作成、編集した際は "必ず" 見て確認すること。 @brawser でも @chrome でもいい。
- webで調べるときは公式だけでなくコミュニティの投稿も調べること。
- 調査・相談・評価を依頼された場合は、その範囲で回答する。ファイル編集、インストール、設定変更などは、ユーザーが実行を依頼してから行う。

## 禁止事項
- 環境変数について、既存の環境変数を上書きするような破壊的行為は禁止する。

## 回答
おすすめする場合は理由を答えること。
例: src/gamesにするとSPAという意味合いになってしまうため、MPAの場合は/gamesと分けたほうが良い。

## Git の権限
Codex は `git add`、`git commit`、`git tag` など `.git` に書き込む操作を、通常権限で試さず、最初から権限付きで実行すること。
もし `index.lock: Permission denied` が出た場合だけ、`index.lock` と Git プロセスの有無を確認する。どちらもなければ、同じ Git コマンドを権限付きで再実行する。`index.lock` は削除しない。

## winget
Windowsでは、通常実行でwingetが見つからなくても、未導入とは断定しない。
Microsoft StoreのWindowsApps実行エイリアスがサンドボックスから見えない場合がある。
wingetを使う必要があるときは、まず権限付きで同じコマンドを再実行して確認する。
許可なくScoopやChocolateyなど別のパッケージ管理ツールへ切り替えない。

## Python
CodexがPythonを使う場合は、Codex内蔵Pythonをデフォルトで使用する。
必要なライブラリが不足している場合は、Codex内蔵Pythonにインストールする。
ユーザーがPython環境を明示した場合、またはプロジェクトでuvを使用している場合は、その環境を優先する。

## PDF
PDFを扱うときは、PDFプラグインを使用する。

## Office
Windows で LibreOffice を CLI 利用する場合は soffice.exe ではなく soffice.com を優先する。
日本語ファイル名で不安定な場合は、ASCII 名の一時コピーを作ってから処理する。
